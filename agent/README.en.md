# anf-agent — the privileged agent

*[Versione italiana](README.md)*

This is the only component that runs as **root**. That is why it is kept
deliberately minimal: no external dependencies, only the Python standard
library.

## Non-negotiable rules

1. **No external dependencies.** Every extra package is extra attack surface on
   a root process.
2. **Never a shell string.** Argument lists are always passed, never
   `shell=True`. Every command has a timeout and a minimal environment
   (`comandi.py` is the only place in the project that spawns external
   processes).
3. **A closed set of verbs.** No generic verb, no "run this".
4. **Path confinement.** The mount point never comes from the API: it is
   derived from the validated slug and stays under `ANF_MOUNT_ROOT`.
5. **Mount options are allow-listed.** An unforeseen option is an error, not a
   value to forward to the kernel.
6. **Only its own units.** The agent never touches a file that doesn't carry
   its marker, so it cannot damage somebody else's configuration.
7. **It refuses to start without root**, instead of silently degrading.

## Communication

A Unix socket, mode `0660`, owned by `root`, group of the application. One JSON
message per line, one reply per line. The agent **opens no network ports**: the
systemd unit runs it with `PrivateNetwork=yes`.

```json
→ {"verbo": "nfs.discover", "dati": {"server": "192.168.1.10"}}
← {"ok": true, "risultato": {"esportazioni": [...], "versioni": ["2", "3"]}}
← {"ok": false, "codice": "validazione", "errore": "Opzione non consentita: 'exec'"}
```

## Verbs

| Verb | Data | Returns |
|---|---|---|
| `ping` | — | confirms the agent answers |
| `nfs.discover` | `server` | exported shares and available NFS versions |
| `mount.create` | `slug`, `server`, `export_path`, `nfs_version`, `automount`, `idle_timeout`, `opzioni` | mount point and generated units |
| `mount.start` | `slug`, `automount` | state after starting |
| `mount.stop` | `slug` | state after stopping |
| `mount.remove` | `slug` | removed units |
| `mount.status` | `slug` | real state of the mount |
| `mount.list` | — | every managed mount, with its state |
| `webserver.detect` | — | which web servers are installed |
| `vhost.preview` | `webserver`, `hostname`, `prefisso`, `porta`, `cartella_pannello`, `prefisso_interno` | the configuration that would be written |
| `vhost.write` | same as `vhost.preview` | writes it, tests it, rolls back on failure |
| `vhost.remove` | `webserver`, `hostname` | removes a vhost generated by the panel |
| `vhost.list` | `webserver` | host names generated by the panel |
| `fstab.list` | — | NFS mounts described in `/etc/fstab` |
| `fstab.disable` | `mountpoint` | comments out that line, after a backup |

## Requested state and effective state

`mount.status` infers nothing from the configuration: it reads the system with
`findmnt` and, if the mount is active, **tries to write** a temporary file. It
is the only way to really know whether writing is possible: the options say
what the client asked for, but the NAS can refuse it on its own.

Two details that look like quibbles and aren't:

- with `x-systemd.automount` the filesystem is mounted **on first access**, so
  the status check touches the path before reading it — otherwise it would
  always report "not mounted";
- a path under automount shows up in `findmnt` first as `autofs` and only later
  as `nfs`: both entries are read and the second one wins.

## Web server configuration

`vhost.write` writes the file, runs `apache2ctl configtest` or `nginx -t`, and
**puts the previous configuration back if the test fails**. A panel that can
leave the web server unable to restart will eventually take the server down.

The output of the test is returned in the error: it is the only thing that
explains what to fix, and hiding it would force someone to read the server
logs.

## fstab

This module **reads only**. Commenting out a line is a separate, explicit
action with a backup of the file: a wrong line in `/etc/fstab` can stop the
machine from booting, and that is not something that should happen as a side
effect of an import. The line is never deleted — it is commented out with a
marker saying who disabled it and when.

## Error codes

`verbo_sconosciuto`, `richiesta_malformata`, `validazione`, `non_trovato`,
`comando_fallito`, `timeout`, `interno`. They let the API react differently: a
validation error is a defect of the panel, a `comando_fallito` is a problem of
the system or of the NAS.

## Layout

```
anf_agent/
├── __main__.py      startup, environment, privilege check
├── server.py        Unix socket, verb dispatch
├── protocol.py      typed messages, allowed verbs, error codes
├── validators.py    security barrier: slugs, paths, options
├── comandi.py       the only place that spawns external processes
├── systemd_units.py generation and removal of .mount / .automount units
├── webserver.py     Apache and Nginx configuration, test and rollback
├── fstab.py         reading and disabling pre-existing NFS mounts
└── nfs.py           export discovery, real state, write probe
```

## Configuration

| Variable | Default | What it does |
|---|---|---|
| `ANF_AGENT_SOCKET` | `/run/anf/agent.sock` | listening socket |
| `ANF_MOUNT_ROOT` | `/srv/nas` | root beyond which nothing is mounted |
| `ANF_AGENT_GROUP` | `anf` | group allowed to talk to the agent |
| `ANF_LOG_LEVEL` | `INFO` | logging level |
